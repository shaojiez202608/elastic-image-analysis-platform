# Threat model

Status: DRAFT (to be reviewed with the deploying team's security reviewers).

Scope: the deployed prototype - API, upload path, workers, endpoint, search domain - in one sandbox account.
No LLM processes untrusted input in this project; the model is an image classifier whose output is still treated
as untrusted data.

## Assets

Uploaded images and their metadata; analysis results; the search index; the model artifact; IAM roles and the KMS
keys; availability of the pipeline (queues, endpoint, domain).

## Entry points

1. API Gateway (IAM-authorised; public Regional endpoint in the sandbox, private endpoint in the handover profile).
2. The presigned POST to S3 (time-limited, key/type/size pinned).
3. Messages on the queues (only principals with SQS permissions in the account can send).
4. The model output object (written by the endpoint, read by the indexer).

## Threats and controls

| # | Threat | Control | Residual risk |
|---|---|---|---|
| T1 | Unauthenticated access to the API | IAM auth on every method; resource policy limits to this account (and VPC endpoint in handover); stage throttling | any principal of the account with execute-api permission can call it |
| T2 | Upload abuse: other key, other type, oversized body, overwrite of another image | key, Content-Type and content-length range are in the signed POST policy (verified in the cloud run); key generated by the API; short expiry | a caller can upload until the policy expires (one object per policy) |
| T3 | Malicious image (parser exploit, decompression bomb, polyglot) | byte cap, magic bytes vs declared type, Pillow pixel limit, verify, re-encode; the model sees only re-encoded images; workers run as non-root with a read-only root filesystem; endpoint with network isolation | parser vulnerabilities in Pillow or the model container (keep images patched; scan on push) |
| T4 | Poison message blocks the queue | unparseable messages acknowledged; transient errors back off; DLQ after max receives; rejected files never retried | DLQ needs an operator (alarm) |
| T5 | Replay / duplicate delivery causing double processing or overwrite | conditional state transitions, deterministic inference IDs, external versioning of documents | a duplicate inference can run if a lease expires during a slow invoke (no duplicate write) |
| T6 | Untrusted model output (wrong types, NaN, huge, injected text) reaching users or logs | size cap; strict schema; only validated fields copied; logs carry field path and keyword | none known within the schema |
| T7 | Search query injection / data exfiltration through the API | allow-listed parameters, fixed patterns, DSL built from validated values; opaque, validated cursor; read-only FGAC role | callers of the API can read all documents (no per-tenant isolation - non-goal) |
| T8 | Privilege escalation via roles | per-role least privilege (SECURITY-NOTES); trust conditions; FGAC role mapping by exact ARN; master role only on the bootstrap Lambda | CDK-managed helper roles use AWS managed basic policies |
| T9 | Data exposure at rest / in transit | KMS everywhere, TLS-only policies, VPC-only domain, no public subnets | account administrators can read everything (shared responsibility) |
| T10 | Denial of capacity (flooding uploads to scale up) | API throttling, `max_*` caps on both layers, oldest-message and DLQ alarms | a flood still consumes capacity up to the caps |
| T11 | Fault-injection switch misused | off in the handover profile; API refuses the field when off; model ignores it unless enabled | sandbox profile has it on by design |
| T12 | Supply chain (base image, packages, model weights) | lock file with cooldown; hash-pinned worker requirements; pinned model revision + SHA-256; pinned image table + checksum; ECR scan on push; osv-scanner and ASH in CI | upstream compromise before pinning |

## Out of scope

Multi-tenancy, end-user identity, WAF, DDoS protection beyond service defaults, production model governance.
